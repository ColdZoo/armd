armd — 机械臂串口守护进程 开发文档

Dynamixel 机械臂串口守护进程：独占串口总线，对上层提供 NDJSON RPC 与发布订阅；持有标定档案（profile）；v0.2.0 起内置安全层（堵转保护 / 软限位 / 单电机故障隔离）。

概览

armd 是机械臂的用户态设备驱动：系统里唯一打开 Dynamixel 串口的进程。 它按固定节拍（默认 60Hz）轮询每条总线上的所有舵机，把状态分发给所有订阅者， 并通过 RPC 接受读/写/标定操作。上层应用（ZeroPose、遥操作、脚本、下位机上的其他服务） 从不直接碰串口，只连 armd。

单进程多臂
一条总线一个 worker 线程；主臂/从臂可同时在线
RPC + 发布订阅
Unix socket / TCP 上的 NDJSON；任意语言可接
标定档案
zero/sign/grip 由 armd 持有，自动历史快照可恢复
安全层
堵转保护 + 软限位 + 单电机故障隔离（v0.2.0）
ARM 下位机
交叉编译 aarch64/armv7，systemd + TCP + token
快速判断"该不该用 armd"：只要你的程序需要读/写机械臂舵机，就应该连 armd； 需要标定后的关节角，直接读 arm.state.deg，不用自己实现换算。

快速开始

1. 启动守护进程（air.my 已用 LaunchAgent 常驻）

# 真机（配置见 ~/.config/armd/config.json）
~/.local/bin/armd --config ~/.config/armd/config.json
# 无硬件自测
armd --sim --socket /tmp/armd-sim.sock

# LaunchAgent 管理（air.my）
launchctl kickstart -k gui/$(id -u)/com.armd   # 重启
launchctl print    gui/$(id -u)/com.armd       # 状态
tail -f /tmp/armd.log                          # 日志

2. 用 Python 客户端调一下

cd ~/nfs/raid/Projects/armd
python3 clients/python/armd_client.py --socket /tmp/armd.sock info
python3 clients/python/armd_client.py --socket /tmp/armd.sock arms
python3 clients/python/armd_client.py --socket /tmp/armd.sock state koch_v1_1:follower

3. 网络/下位机场景

armd --config /etc/armd/config.json       # 板上：listen 含 tcp://0.0.0.0:8771 + token
python3 clients/python/armd_client.py --socket tcp://arm-board.my:8771 --token $ARMD_TOKEN arms

架构与队列

客户端 A（ZeroPose） 客户端 B（遥操作） 客户端 C（脚本/agent） │ RPC/订阅 │ │ └──────────────┬───────┴─────────────────────┘ ▼ Unix socket 或 TCP（NDJSON） ┌───────────────────────────┐ │ armd │ │ conn 线程 × N（每客户端） │ │ writer 线程（响应+推送） │ ├───────────────────────────┤ │ arm worker（每条总线一个）│ │ urgent 队列 64 │ │ normal 队列 256 │ │ 每订阅者有界队列 32（丢帧）│ │ 60Hz sync_read 合并 │ └──────────┬────────────────┘ ▼ /dev/cu.usbmodem*（Dynamixel 总线，1Mbps）
  • urgent(64)：写寄存器 / 扭矩 / sync_write / 重连，每轮优先全清，写命令到总线延迟 ≤2ms。
  • normal(256)：读快照、ping、改速率等，每轮最多 16 条，保证轮询不被饿死。
  • 轮询合并：一次 sync_read 读全部电机，结果写状态缓存；所有订阅者共享这次读数。
  • 发布背压：每个订阅者一个容量 32 的有界队列，满了丢帧并计数（frames_dropped），慢客户端不拖累总线。
  • 订阅速率：rate_hz ≥ 54 时直通（每个轮询帧都推）；更低频率按时间抽帧。
  • 自愈：连续 3 次传输层读失败判掉线 → 先 close 释放 fd 再每 reconnect_sec（默认 2s）重连；连接时 ping 全部电机握手，≥1 个响应即 connected（单电机故障只记 per-motor error）。
  • 安全层（v0.2.0）：每电机 StallTracker 堵转检测（默认 400ms → torque OFF + goal 回退 + event:"stall"）；写 Goal 前软限位（EEPROM Min/Max）；单电机 hardware error 只标记该电机，不再拖垮整臂 worker。详见 安全层。
  • 单实例：打开串口前先拿 <socket>.lock（File::try_lock）；启动时探测已有 socket，活的拒绝抢占、死的清理。

安全层（v0.2.0，三道防线）

2026-11-22 事故：从臂肘部（motor 3，XL430/XL330）顶住机械限位持续输出力矩 → 舵机 latch hardware error 0x80 → follower worker 读失败/重连 → 串口 fd 未释放，Device or resource busy 无法恢复，只能重启 armd + 物理断电。事故记录见 docs/INCIDENT-2026-11-22.md，冻结规范见 docs/SAFETY-DESIGN.md。v0.2.0 把「不把机械臂顶坏、不让单电机拖垮整臂、不泄漏串口 fd」固化为三道防线。

三道防线

防线触发条件动作如何观察/验收默认值
① 堵转保护（最后一道防线）每电机 StallTracker：|goal - present| > stall_tolerance(60) 且 |velocity| <= stall_velocity_epsilon(2) 且 torque_on，持续 stall_timeout_ms(400)；stall_exclude_motors 里的电机跳过只对该电机：先 sync_write Torque_Enable=0（auto_torque_off=true 时，默认开）→ goal 回退到 present 附近（夹到 [min+stall_recover_margin, max-stall_recover_margin]）→ state.stalls + stats.stalls + event:"stall"；同臂其他电机完全不受影响arm.state.stalls / event:"stall"；arm.read_register(motor, 64, 1) 应读到 0；不会产生 0x80stall_protection=true, stall_timeout_ms=400, stall_tolerance=60, stall_velocity_epsilon=2, auto_torque_off=true, stall_recover_margin=20, stall_exclude_motors=[]（建议夹爪填 [6]）
② 软限位（写 Goal 前拦截）写 Goal_Position(116)（arm.write_register / arm.sync_write）且 soft_limits=true；生效范围由该电机的 Operating_Mode(11) 决定位置模式(mode 3) 或模式未知：先夹到绝对范围 0..=4095，再按 EEPROM Min/Max Position Limit 夹到 [min+soft_limit_margin, max-soft_limit_margin]；扩展位置模式(mode 4)：只夹到绝对范围 ±1,048,575，不套 EEPROM Min/Max（它只适用于单圈位置模式，否则多圈目标会被错误夹住）。clamp 模式（默认）下发夹紧值并回 clamped/warnings；reject 模式返回 soft_limit 错误、不下发mode 3 下 arm.write_register(116, 5000) → applied=4095-margin 或 soft_limit 错误；mode 4（主臂）允许负值/>4095 的多圈目标；写成功清除该电机 stall 标记。worker 连接时读 Operating_Mode 并每秒刷新、跟踪对 addr 11 的写入（遥操作启动时把从臂切到 3）soft_limits=true, soft_limit_mode="clamp", soft_limit_margin=10
③ 单电机故障隔离 + 串口 fd 生命周期某个舵机状态包 error 位非 0（如 0x80）或连续 ≥10 次轮询无响应sync_read 按电机返回 {data, errors}，单电机 error 只写 motor_errors[id]（事件 motor_error），connected 保持 true、其他电机正常；故障恢复自动清除并发 motor_recovered；Link 保证 open 前先 close 旧句柄、读失败 3 次先 close 再重连，打开失败时 io=None，绝不占着 fd 再 openarm.list[].motor_errors / arm.state.motor_errors；fd 不变量：connected 期间 opens - closes == 1（恰好一个 live 串口句柄），断线释放后二者相等；arm.reconnect ×20 后 lsof 每设备仍只有 1 个 fd；用 sim.inject transport_error 可验证断线后 fd 先释放无需配置；connected 语义见 arm.state.connected

恢复流程

latched 硬件错误（0x80 hardware_alert）恢复

  1. arm.list 或 arm.state 确认 motor_errors[电机].code == 128（names 含 hardware_alert），记下电机 id
  2. arm.state.stalls 查看是否由堵转触发；排查机械卡死/限位/NFS 等外部原因
  3. arm.reboot(motors=[该电机]) —— Dynamixel Reboot(0x08) 清除 latched 错误（最长等 5s；成功时 torque 自动置 false）
  4. arm.clear_error(motors=[该电机]) 只清 armd 侧标记；若 hardware_error_status 仍非 0，warnings 会提示必须 reboot/断电
  5. 确认 motor_errors 已空、connected=true 后，再 arm.torque(enable=true) 恢复使能（或重新写目标）

堵转触发后恢复

  1. arm.state.stalls[电机] 看 position/goal/stall_ms/reverted_goal；event:"stall" 可实时发现
  2. 排除机械卡死：手动活动关节、检查线缆/限位/负载，确认不是软件目标导致顶死
  3. 需要继续动作时：先给安全的新目标（arm.write_register 116 或 arm.sync_write，会先过软限位），或在应用里把目标收回到可达范围
  4. target 更新成功后该电机 stall 标记自动清除；再 arm.torque(enable=true) 重新使能
  5. 反复触发说明负载/限位/标定参数有问题，不要简单关掉 stall_protection

串口 Device or resource busy / fd 泄漏（事故根因）

  1. v0.1.0 中读失败后旧 fd 不释放、再次 open 永远 EBUSY（lsof 可见每设备多 fd）。升级 v0.2.0 后该根因已修复
  2. 现场处置：升级 armd → arm.reconnect（先 close 再 open，fd 立即释放）→ 仍 busy 时用 lsof /dev/cu.usbmodem* 确认没有其它进程占用（zeropose 直连等）
  3. 设备节点消失/仅剩旧 fd：unplug 后重新插上，armd 会自动重连；用 arm.stats.opens/closes 判断是否有泄漏：connected 期间差值为 1（恰好一个 live 句柄），断线释放后二者相等；差值 >1 才说明泄漏
  4. latched 0x80 不会因重连消失，必须 arm.reboot 或物理断电；连不上总线时 arm.list.error 会给出 open 错误

注意事项

  • 堵转检测依赖轮询窗口里的 Present_Velocity。poll_addr 未显式配置且 stall_protection=true 时，poll 窗口自动用 addr=128、len=8（一次 sync_read 同时读 velocity+position，只多 4 字节/电机）；显式配置 poll_addr/poll_len 时维持旧语义，velocity 未知 → 堵转检测自动跳过并打一条警告日志。
  • arm.read/arm.state 的 errors 是「该电机状态包带 error 位」，不是传输失败；完全没响应的电机不出现在 data/errors 中，连续 ≥10 次（约 167ms@60Hz）标记 no_response。
  • 夹住物体时夹爪的电机会持续存在 Goal-Present 偏差且 velocity≈0，属正常保持而非堵转。用 stall_exclude_motors 把夹爪（如 6）排除出堵转自动保护；本仓库 configs/koch*.json 已写 [6]。事故中的 motor 3（肘部）不在排除列表里。
  • 软限位按 Operating_Mode(11) 生效：位置模式(mode 3) 用 EEPROM Min/Max 且绝对 0..4095；扩展位置模式(mode 4) 只做 ±1,048,575 绝对范围，不套 EEPROM 限位（主臂真实电机是 mode 4）。worker 连接时读 Operating_Mode，每秒刷新并跟踪对 addr 11 的写入（遥操作启动时会把从臂切到 3）。
  • 多圈关节（主臂 mode 4）的 state.joints / state.velocity / goals 可以超出 0..4095（实测 pan 6133、roll -2889），这是正常的多圈位置，不是坏值；换算角度时由 profile 的 wrap 逻辑处理。
  • fd 不变量：connected 期间恰好有 1 个 live 串口句柄，即 stats.opens - stats.closes == 1；worker 关闭/断线释放 fd 后两者相等。arm.sim.inject 的 transport_error 往整条总线注入传输错误（模拟 USB 掉线），worker 连续 3 次传输失败后先 close 释放 fd 再按 reconnect_sec 重连，可用于验证释放路径；清除注入后恢复。
  • 所有新配置项均可省略（serde default），旧 v0.1.0 配置无需改动；旧客户端可忽略新增字段。

传输与协议

帧格式：NDJSON：一行一个 JSON。请求/响应用 id 配对；推送帧带 event 字段、无 id。

Unix socket：/tmp/armd.sock（macOS/Linux 本机；权限 0600）
TCP：tcp://host:8771（下位机/网络场景，配置 listen 里开启）
鉴权：配置 token 后，客户端必须先发 hello 带 token，否则所有方法返回 unauthorized。
JSON-RPC 2.0：兼容 JSON-RPC 2.0：请求带 "jsonrpc":"2.0" 时响应也带。

请求 / 响应 / 错误

→ {"id": 7, "method": "arm.state", "params": {"arm": "koch_v1_1:follower"}}
← {"id": 7, "result": {"seq": 123, "connected": true, "joints": {"1": 1511}, "deg": {"shoulder_pan": 43.24}, "torque": {"1": true}, "goals": {"1": 1511}, "stalls": {}, "motor_errors": {}, "safety": {"stall_protection": true, "stall_timeout_ms": 400, "stall_tolerance": 60, "auto_torque_off": true, "soft_limits": true, "stall_exclude_motors": [6]}}}
← {"id": 7, "error": {"code": "no_such_arm", "message": "unknown arm 'x'"}}

请求不带 id 也可（单向命令），但写操作建议带 id 等确认。

方法说明

标定档案 profile

标定档案：raw→URDF 关节角的换算参数。存在 ~/.config/armd/profiles/<arm-id>.json。

字段含义
zero{joint: raw}
sign{joint: 1|-1}
gripopen：int
closed：int
angle：float (5~140.5, 可选)
spinwrist_roll：float (-180~180, 可选)
savedAtint (unix 秒)

换算公式

# 非夹爪关节
deg = wrap(raw - zero)   # 折到 ±2048（连续关节可整圈，避免 ±180° 跳变）
deg = deg * 360 / 4096 * sign
# 夹爪
deg = clamp((raw - closed) / (open - closed), 0, 1) * (angle 或 137.5)

读写 / 历史 / 恢复

c.profile(arm) -> {profile, path, has_profile}
c.set_profile(arm, profile)     # 校验 + 原子写；覆盖前自动快照到 profiles/history/（保留 20 份）
c.profile_history(arm)          # [{name, savedAt}]
c.restore_profile(arm, name)    # 从历史快照恢复
c.calibration_snapshot(arm)     # 采点：raw(按关节名)+deg+health，不占总线
armd 是标定数据的唯一事实源。ZeroPose 的「保存到真机」通过 arm.profile.set 写入；本地 ~/.config/zeropose/*.json 只是镜像备份。

客户端与示例

Python 客户端：clients/python/armd_client.py（纯标准库，支持 Unix/TCP/token）。

from armd_client import ArmdClient  # clients/python/armd_client.py（stdlib）

c = ArmdClient("/tmp/armd.sock", token=None)      # 下位机：ArmdClient("tcp://arm-board:8771", token=...)
print(c.arms())                                    # 所有机械臂摘要
print(c.state("koch_v1_1:follower")["deg"])        # 标定后的关节角（度）
print(c.read("koch_v1_1:follower")["positions"])   # 立刻 sync_read 一次 raw

# 订阅 60Hz 状态流
import time
frames = []
sub = c.subscribe(lambda f: frames.append(f), arms=["koch_v1_1:follower"], rate_hz=60)
time.sleep(1)
print("frames/s ≈", len(frames))
c.unsubscribe(sub)

# 安全层（v0.2.0）
print(c.safety("koch_v1_1:follower"))               # stalls / motor_errors / torque / limits / goals / safety
print(c.state("koch_v1_1:follower")["motor_errors"])
c.torque_off("koch_v1_1:follower")                  # 应急卸力矩（可传 motors=[3]）
c.reboot("koch_v1_1:follower", motors=[3])          # Dynamixel Reboot(0x08) 清 latched 0x80
c.clear_error("koch_v1_1:follower")                 # 清 armd 侧 error/stall 标记
# c.sim_inject("koch_v1_1:follower", "stall", motors=[3])  # 仅 sim 臂：stall/hardware_error/no_response/clear

# 标定档案
prof = c.profile("koch_v1_1:follower")["profile"]
c.set_profile("koch_v1_1:follower", prof)          # 覆盖前 armd 自动留历史
print(c.profile_history("koch_v1_1:follower")["history"])
c.restore_profile("koch_v1_1:follower", c.profile_history("koch_v1_1:follower")["history"][-1]["name"])
c.close()

排障 FAQ

启动失败：另一个 armd 已经持有 …lock

单实例锁 <socket>.lock 被占用。先确认没有在跑的 armd（pgrep -fl armd）； 锁文件本身不需要删除（进程退出内核自动释放）。

Device or resource busy / 串口 fd 泄漏

这是 v0.1.0 事故的根因（详见 docs/INCIDENT-2026-11-22.md）：读失败后旧 fd 未释放， TIOCEXCL 让再次 open 永远 EBUSY。v0.2.0 已修：Link 保证 open 前先 close，读失败 3 次先释放 fd 再重连。 处置：升级 v0.2.0 → arm.reconnect（立即 close 再 open）→ 仍 busy 用 lsof /dev/cu.usbmodem* 确认没有其它进程（如 zeropose 直连）占用；插拔 USB 后 armd 会自动重连。 fd 不变量：connected 期间 stats.opens - stats.closes == 1，断线释放后二者相等。

舵机报 latched 硬件错误 0x80（hardware_alert）

典型是堵转/顶住限位后舵机 latch 的错误，普通重连不会清除。 用 arm.reboot（Dynamixel Reboot 0x08，最长 5s）清除；arm.clear_error 只清 armd 侧标记， 若 hardware_error_status 仍非 0，warnings 会提示必须 reboot/断电。详见 安全层。

收到 event:"stall" / state.stalls 有记录

堵转保护已触发：该电机 torque OFF + goal 回退到限位内侧。先排除机械卡死/限位/负载问题， 再给安全的新目标（写入即清除该电机 stall 标记）并 arm.torque(enable=true)。 夹爪夹住物体时 Goal-Present 长期有偏差属正常——已在 shipped configs 用 stall_exclude_motors: [6] 排除，不要靠关掉 stall_protection 解决反复触发。

单个舵机不动，但其它电机/订阅正常

v0.2.0 起单电机故障被隔离：看 arm.list[].motor_errors / arm.state.motor_errors。 code=128 是 latched 硬件错误（用 arm.reboot）； code=null / names 含 no_response 是连续 ≥10 次读不到（检查供电/线缆/ID）。 connected 仍为 true 是预期行为，不再整臂掉线。

macOS：进程刚起就被 SIGKILL（Code Signature Invalid）

拷贝过的二进制需要重签：codesign --force --sign - ~/.local/bin/armd；用 scripts/deploy-macos.sh 可避免。

Linux 板子：舵机全都不响应

99% 是串口被别的程序占用：lsof /dev/ttyACM0 或 fuser -v /dev/ttyACM0； Armbian 常见 serial-getty@ttyS2，sudo systemctl mask serial-getty@ttyS2。

连接被拒 / 全部 unauthorized

配置了 token：客户端连接后必须先发 hello（Python 客户端传 token= 或环境变量 ARMD_TOKEN 会自动发）。

订阅帧数比 60 少

rate_hz < 54 会按时间抽帧；要 60Hz 直通就传 rate_hz: 60。 也可能是客户端读得慢：看 arm.stats.frames_dropped。

网页/应用一直显示旧数据

检查订阅连接是否中断：状态帧 ts 超过 1 秒没更新应视为掉线并重连（ZeroPose 已内置）。 armd 重启后客户端需要重新 subscribe。

版本与兼容

  • v0.2.0（2026-11-22）：安全层：堵转保护（400ms 默认，torque OFF + goal 回退 + 事件）、Operating_Mode 感知软限位（mode 3 用 0..4095+EEPROM 限位，mode 4 用 ±1,048,575 绝对范围；clamp/reject）、单电机故障隔离（per-motor errors，connected 保持 true）；新增 RPC：arm.reboot / arm.clear_error / arm.torque_off / arm.sim.inject；arm.read 带 errors；write/sync_write 带 clamped/warnings；新增事件：stall / motor_error / motor_recovered；state 帧新增 velocity/goals/torque/limits/motor_errors/stalls/safety；stats 新增 stalls/torque_offs/opens/closes；串口 fd 生命周期修复：open 前先 close，连续读失败先释放 fd 再重连，断线不再 100% CPU 自旋（事故根因）；新增配置：stall_* / soft_limit_* / stall_exclude_motors（默认即安全，旧配置兼容）。
  • v0.1.0（2026-11）：JSON-RPC 2.0 兼容、token 鉴权、Unix+TCP 双传输；标定档案 profile + 历史快照/恢复；电压/温度监控、ARM 交叉编译产物；订阅限流、单实例锁 + identity 文件。
  • 协议稳定性：方法名/字段只增不改；新增可选字段老客户端可忽略。
  • 机器可读规范：docs/api.json（本页由它生成：python3 scripts/gen-armd-doc.py）。
